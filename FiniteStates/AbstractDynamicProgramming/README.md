# Abstract dynamic programming in Lean

This is the `FiniteStates/AbstractDynamicProgramming/` proof project in
[LeanEconomics/DynamicProgramming](https://github.com/LeanEconomics/DynamicProgramming).
Run the commands below from this directory: `cd FiniteStates/AbstractDynamicProgramming`
from the repository root. [Return to the library index](../../README.md).

A checked formalisation of Sargent and Stachurski, *Dynamic Programming*,
Volume 1: *Finite States*, Chapter 9, "Abstract Dynamic Programming"
(pp. 292–307), with the proofs of Appendix B.4 (pp. 349–351), including every
provable exercise (Exercises 9.1.1 and 9.2.1–9.2.7). The library contains
**241 theorems** and audits every declaration, including structure constructors and
projections.

* **Order stability** (§9.1.1): upward, downward and order stability of self-maps of a
  partially ordered set, with no topology; Exercise 9.1.1 (`v ↦ r + Av` with `A ≥ 0`,
  `ρ(A) < 1`), Lemma 9.1.1 (order-preserving globally stable maps are order stable) and
  Lemma 9.1.2 (order duality).
* **Abstract dynamic programs** (§9.1.2, §9.2.1): `(V, {T_σ})` on a partially ordered set
  with greatest and least elements of every `{T_σ v}`; greedy policies, the Bellman
  operator `⋁_σ T_σ` (Exercise 9.2.1), `V_Σ ⊆ V_u` (Exercise 9.2.3), the Howard operator
  and HPI; Lemma B.4.1, Proposition 9.2.1 (finite and order stable implies max-stable),
  Proposition 9.2.5 (max-stable ADPs) and **Theorem 9.2.4** (max-optimality, with finite
  termination of HPI). HPI terminates because a strictly increasing value sequence would
  inject `ℕ` into the finite policy set.
* **Examples** (§9.1.2–§9.2.1): ADPs generated by RDPs (Example 9.1.1, Corollary 9.2.2),
  Proposition 9.2.3 (on an order interval, well-posed iff order stable, by
  Knaster–Tarski), MDPs with `v_σ = (I − βP_σ)⁻¹r_σ` (Examples 9.1.2, 9.2.1), Q-factors
  (Example 9.1.3, Exercise 9.2.2: max-stable) and risk-sensitive Q-factors
  (Example 9.1.4).
* **Proofs of the RDP results** (§9.2.2): Theorem 9.2.4 for `A_R` translated to `R`;
  the OPI Lemmas 9.2.6–9.2.10; **Theorem 8.1.1** (i)–(v) and, through the reduced RDP on
  `[v₁, v₂]` and Proposition 9.2.3, **Theorem 8.1.2**.
* **Mixed strategies** (§9.2.1.6): Exercises 9.2.4–9.2.6, the mixed-strategy ADP with
  Bellman operator `T` (9.6), and, for a contracting RDP, the equality of its value
  function with `v*`: mixing does not raise lifetime value.
* **Min-optimality** (§9.2.3): the dual ADP, Exercise 9.2.7, **Theorem 9.2.11** and
  min-HPI, and min-stability of `A_R` for globally stable `R`.

The main entry points are `orderStable_restrict`, `ADP.IsOrderStable.maxOptimality`,
`ADP.IsMaxStable.optimality`, `RDP.toADP_wellPosed_iff`, `MDP.qADP_isMaxStable`,
`RDP.optimality_of_globallyStable`, `RDP.optimality_of_bounded`,
`RDP.mixed_value_eq_vstar` and `ADP.minOptimality`, all in the namespace
`SargentStachurski.AbstractDynamicProgramming`.

See the [source map](docs/source-map.md) for the correspondence with the book,
result by result. [Corrections](docs/corrections.md) records the hypotheses the book
leaves implicit (a nonempty policy set in Proposition 9.2.1; mixed policy operators
mapping `V` into itself; `m ≥ 1` in the OPI lemmas) and what is not formalised.

## Build and verify

```sh
lake exe cache get
python scripts/verify.py
```

The verifier builds the library, freshly recompiles every contributed proof,
and audits each named declaration's axioms (only `propext`, `Classical.choice`
and `Quot.sound` are allowed). Warnings fail the check.
